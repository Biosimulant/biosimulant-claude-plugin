# Build or adapt a model

Inspect the connected server's available tools and schemas. Explain model choices and approval requests in plain English, with the relevant scientific detail.

1. Clarify the scientific question, available data, and what the model needs to predict or explain. Check the user's existing lab before making a new one. When reusing a published model, inspect the exact release, inputs, outputs, units, assumptions, runtime, license, and attribution. Explain what can be reused and what needs to change.
2. For implementation, preserve source references and executable interfaces. Work in the correct private lab or copy, and preview the exact edits through the connected server. Apply them only under the current permission and approval rules. Test the behavior the user needs with real or clearly labeled example inputs. Report what was saved and which tests actually ran.
3. For a formal design request, use [Define what the model must do](references/requirements/workflow.md) to capture requirements and tests that could demonstrate them. Use [Plan how to build and test the model](references/technical-plan/workflow.md) when the requirements are approved. Keep templates and validation guidance with these steps. They are optional for ordinary modeling work.

Example: “Find a published model I can adapt for my question. Explain what it assumes and what I'd need to change.”
